# API Reference

Two contracts, both living in the repo under `apis/` and both linted by
Spectral in CI on every push:

| Contract | File | Where in these docs |
| --- | --- | --- |
| REST | `apis/openapi.yaml` (OpenAPI 3.0.3) | [REST API](./rest/workforce-management-api.info.mdx) — **generated from the spec**, interactive |
| Events | `apis/asyncapi.yaml` (AsyncAPI 2.6.0) | [Events](./events.md) — hand-authored from the spec |
| Errors | — | [Errors](./errors.md) — the RFC 7807 shape and every problem type |

The REST pages under **API Reference → REST API** are generated by
`docusaurus-plugin-openapi-docs` directly from `apis/openapi.yaml`. They are not
transcribed by hand, so they cannot drift from the spec.

## Every endpoint

documented in `apis/openapi.yaml`.** The one missing from the spec is the
readiness probe `GET /readyz` ([ADR 0022](../adr/0022-resilience-circuit-breakers-retry-dlq-shutdown.md)),

Grouped by OpenAPI tag: **Associates** (5), **Shift Plans** (2),
**Assignments** (1), **Staffing** (2), **System** (2).

The two creation POSTs are wrapped in the transactional `Idempotency-Key`
middleware ([ADR 0027](../adr/0027-idempotency-key-middleware.md)) whenever
the service runs on Postgres (every deployment): a missing key is
`400 idempotency-key-required`, the same key with a different body is
`422 idempotency-key-reused`, and a retry with the same key and body replays
the stored response.

## Conventions

**Resource creation returns `201` with a `Location` header.** Starting a shift,
committing a plan and creating an assignment all do this. Commands with no new
resource to point at return `204 No Content`.

**Errors are always RFC 7807.** Content type `application/problem+json`, never
a bespoke `{"error": ...}` shape. See [Errors](./errors.md).

**Two verbs that look like RPC, and why they stay.**
`POST /associates/{id}/start-shift` and `.../end-shift` are state transitions on
a roster entry, not resources. Modelling them as `PATCH` on an
`/associates/{id}/shift` sub-resource with a status field would be more
literally REST-shaped and less legible: "start-shift" is what the domain calls
it, and the ubiquitous language wins. They are Level 2 on the Richardson
maturity model — correct verbs, correct status codes, resource-scoped URLs —
which is where this API deliberately sits.

**Identifiers are opaque strings.** `associateId`, `pathId`, `siteCode` (the
deprecated alias `buildingId` is the same value) and
`shiftId` are validated as non-empty and otherwise uninterpreted. `pathId` is a
*process path* name — `pack`, `pick`, `stow` — never a physical location.

## DTOs never leak domain types

Request and response bodies are declared in
`internal/adapters/inbound/http/dto.go` as adapter-local structs. No domain
aggregate is ever serialised directly. That is what allows the JSON contract
and the domain model to evolve on separate clocks — and it is checked by the
`arch-go` fitness tests, not just by convention.
